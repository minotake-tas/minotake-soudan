# 公開ページの補助監視

初期状態は停止です。`tools/public_page_monitor.config.json` の `enabled` は `false` です。
今回の承認は手元のコピーでの実装と架空の応答による試験までです。
送信・取り込み・定期確認開始・実メールの受信試験は、別の承認が必要です。

## 確認する範囲

チラシの入口と11月19日分の申込み画面、固定の２ページだけを開きます。
画面のリンクを巡回せず、別ページへの移動も追いません。
ログイン、予約申込み、ライン通知、メール送信は行いません。鍵も使いません。
受付開始は日本時間2026年11月9日午前９時です。開始前は日時の案内、開始後は入力欄を確認します。
開催日・両会場・見出し・申込みボタンも確認します。隠し文字やスクリプト内の文章は正常の証拠にしません。

１回の読み込みは10秒まで、１ページ１メガバイトまでです。失敗した対象は15秒待って１回だけ再確認します。
２ページとも失敗する場合、最大４回の読み込みと合計30秒の待機になります。
記録するのは時刻・固定の対象名・定型の理由・応答番号だけです。ページ本文・入力値・例外の文章は記録しません。
公開ページの連絡先欄に値が入っていた場合は正常扱いにせず、値自体は記録しません。

## 起動と通知

設定を有効にした場合、ギットハブの自動実行機能が毎時７・22・37・52分を目安に確認します。
主ブランチ以外や別の保管場所では公開確認を実行しません。変更案の試験では架空の応答だけを使います。
追加の外部ソフト・鍵・有料実行環境・保存用の添付データ・キャッシュは使いません。
自動実行は遅延・欠落する場合があり、15分以内の検知を保証しません。

異常が続く場合は実行結果を失敗にします。メールはギットハブ標準の失敗通知を使う想定です。
送信先をコードへ埋め込まず、実際の受信者と通知設定を本人の画面で確認します。
定期実行の通知は、設定した本人や、実行日時を最後に変更した人などが対象になります。
そのため、作成しただけでは本人へメールが届くとは断定できません。受信設定と実メールは未確認です。
開始前に「失敗のみメール通知」を確認し、本人承認後、架空の失敗による受信試験を行います。

## 停止と開催後

日本時間2026年11月20日午前０時以降は、公開ページへの通信を行いません。
定期確認の経路は、コード取得より前にも終了日時を確認します。
定期起動の設定自体は残るため、終了後に本人の操作で「公開ページの補助監視」を無効にする候補です。
途中で止める場合も、ギットハブの自動実行一覧からこの名前の処理だけを無効にします。
これは補助監視の停止です。予約受付、職員画面、ライン通知の停止とは別です。
再開するときは停止期限、ページの文言、本人の通知設定を確かめます。

## 分かることと分からないこと

応答なし、正常でない応答番号、別ページへの移動、ログイン画面、案内・入力欄の欠落を見つける補助です。
実際に予約が保存できること、枠の確保、暗号化、ラインの到達、携帯での操作をこの監視だけで保証しません。
外部の見た目の指定で隠された文字や、ブラウザー内の処理が動くかまでは判断しません。
本番に対する確認は、既存の通し試験と分けて記録します。

## 手元で行う試験

`python3 -m unittest discover -s tests -p 'test_public_page_monitor.py' -v`

すべて架空の応答を使います。実ページに対する定期確認、予約登録、実メール、鍵の操作は行いません。
`python3 tools/public_page_monitor.py` は停止設定を読み、通信せずに終了することも確かめます。

全サービスの追加費用が必ず０になる保証ではありません。

極端な入れ子（128段以上）や要素数（２万超）は読み取りを中止します。別々の入力枠を合算して正常とは判定しません。
